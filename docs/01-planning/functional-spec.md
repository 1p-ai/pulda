# 기능정의서

- 문서 상태: Draft / Living Document
- 기준일: 2026-07-04

## 1. 공통 기능

### 1.1 전역 내비게이션

- 제공 위치: 홈, 소개, 프로젝트, 스토리, 문의, 상세 페이지
- 메뉴: 소개, 과제/Project, 이야기/Story, 만남/Contact
- 라이트 모드: 한글 중심 라벨과 전통적 시각 언어
- 다크 모드: 영문 중심 라벨과 테크 시각 언어
- 모바일: 메뉴 버튼으로 열고 닫는다.

### 1.2 테마 전환

- 사용자는 라이트/다크 테마를 선택할 수 있다.
- 선택값은 localStorage의 pulda-theme에 저장한다.
- 저장값이 없으면 시스템 다크 선호도를 초기값으로 사용한다.
- 테마 결정 스크립트는 CSS보다 먼저 실행되어 페이지 이동 시 깜빡임을 방지한다.

### 1.3 SEO 메타

- 모든 주요 페이지는 title, description, canonical을 제공한다.
- 상세 콘텐츠는 publishedAt, updatedAt, tags 기반 구조화 데이터를 제공한다.
- sitemap, RSS, robots를 정적 생성한다.

## 3. 소개

- Pulda의 문제 해결 방식과 협업 태도를 설명한다.
- 메인에서 이미 철학을 제시하므로 과도한 구조 확장보다 문구 정밀도를 우선한다.
- 프로젝트 페이지로 이동하는 CTA를 제공한다.

## 4. 프로젝트

### 4.1 목록

- projects 컬렉션을 최신순으로 표시한다.
- draft가 true인 항목은 제외한다.
- client, services, tags, outcome을 표시해 케이스 스터디 성격을 드러낸다.
- 대표 프로젝트는 포트폴리오 전시 성격을 강화할 수 있도록 시각 자료가 충분한 항목을 우선한다.

### 4.2 상세

- 프로젝트명, 설명, 연도, 클라이언트, 범위, 결과 요약을 표시한다.
- 본문은 Markdown/MDX Content로 렌더링한다.
- 프로젝트별 기획 의도, 진행 과정, 리뷰, 산출물을 보여준다.
- 가로형 이미지, 디바이스별 화면, 세로 스크롤 캡처, 갤러리형 이미지를 콘텐츠 흐름에 맞게 배치할 수 있어야 한다.
- 자산의 관리 상태는 방문자에게 그대로 노출하지 않는다. 방문자는 하나의 완성된 케이스 스터디로 보게 한다.
- 목록으로 돌아가는 링크를 제공한다.

## 5. 스토리

### 5.1 목록

- stories 컬렉션을 최신순으로 표시한다.
- draft가 true인 항목은 제외한다.
- category, author, publishedAt, title, description을 표시한다.
- 첫 화면에는 대표 글과 최근 글을 구분해 편안한 블로그 탐색 경험을 제공한다.
- 초기에는 카테고리 탭을 강하게 노출하지 않고, 글이 쌓인 뒤 태그/카테고리 기반 탐색을 강화한다.

### 5.2 상세

- 제목, 설명, 카테고리, 작성자, 발행일을 표시한다.
- 본문은 읽기 중심의 좁은 폭으로 제공한다.
- 하단에는 관련 스토리 또는 목록 복귀 경로를 제공한다.
- 광고 실험이 필요한 경우 본문 중간이 아니라 글 읽기가 끝난 뒤의 낮은 방해 영역에서만 검토한다.

## 6. 문의

- 이메일 문의 링크를 제공한다.
- 현재는 별도 문의 폼 없이 mailto 기반으로 운영한다.
- 향후 필요 시 Google Forms, Sanity, 외부 CRM, 서버리스 폼 처리로 확장 가능하다.

## 7. 운영 포털

- /admin은 Sanity Studio가 아니다.
- /admin은 운영자가 실제 관리 도구로 이동할 수 있는 내부 포털이다.
- 제공 항목은 Sanity Studio, Google Analytics, Google Search Console, 네이버 애널리틱스, 배포 체크리스트, 콘텐츠 운영 기준이다.
- /admin에는 가짜 저장, 가짜 등록, 가짜 삭제 기능을 두지 않는다.
- 정적 사이트에 배포되는 /admin은 noindex와 robots disallow를 적용하되, 실제 보호는 Cloudflare Access 같은 호스팅 레벨 접근 제어로 처리한다.

## 8. CMS 예정 기능

- 실제 콘텐츠 CRUD는 Sanity Studio가 담당한다.
- 문서 타입은 project, story, siteSettings를 우선한다.
- 발행 Webhook으로 정적 사이트를 재빌드한다.
- 공개 데이터셋 전제이므로 민감 정보는 CMS에 저장하지 않는다.

## 9. 통계와 광고

- 접속 통계는 사이트 내부 관리자 화면에서 원본 데이터를 재구현하지 않는다.
- 운영자는 외부 분석 도구에서 지표를 확인하고, /admin은 해당 도구로 이동하는 관문 역할을 한다.
- 광고는 브랜드 신뢰를 해치지 않는 범위에서만 검토한다.
- 홈, 소개, 문의 페이지는 광고 비노출을 기본 정책으로 둔다.
- 프로젝트와 스토리도 기본은 비활성화이며, 필요 시 하단 영역에서 제한적으로 A/B 또는 기간 테스트를 한다.
