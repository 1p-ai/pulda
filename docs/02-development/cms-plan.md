# CMS 도입 계획

- 문서 상태: Draft / Living Document
- 기준일: 2026-07-04

## 1. 방향

초기에는 Markdown으로 콘텐츠 구조와 SEO를 검증한다. 운영자가 개발자 도움 없이 프로젝트와 스토리를 발행해야 하는 시점에 Sanity Studio를 실제 콘텐츠 관리 도구로 도입한다.

사이트 내부의 /admin은 Sanity Studio가 아니다. /admin은 운영자가 Sanity, 통계 도구, 배포 체크리스트로 이동하는 운영 포털이며, 방문자에게 공개되어도 되는 일반 화면이 아니라 내부 접근 제어 대상이다.

## 2. Sanity Free 플랜 활용 기준

- Pulda 초기 콘텐츠 운영에는 무료 플랜으로 충분하다.
- 공개 데이터셋 전제이므로 비공개 제안서, 계약 정보, 내부 리뷰, 고객 민감 정보는 저장하지 않는다.
- 이미지/문서 자산은 공개 가능한 대표 이미지와 콘텐츠용 이미지 위주로 관리한다.
- 프로젝트 포트폴리오용 원본 이미지, 시안 캡처, 디바이스별 캡처는 공개 가능한 선별본만 CMS에 등록한다.
- 운영 중 망가진 외부 사이트 화면을 그대로 보여주지 않도록, 관리된 대표 자산을 프로젝트 콘텐츠의 기준 이미지로 둔다.

## 3. Studio 구성

| 문서 타입 | 목적 | 우선순위 |
| --- | --- | --- |
| project | 프로젝트 케이스 스터디 작성 | P0 |
| story | 기업 블로그/저널 작성 | P0 |
| siteSettings | 연락처, 대표 노출 콘텐츠, 기본 메타 관리 | P1 |
| mediaAsset | 프로젝트별 관리 이미지의 용도, 출처, 대체 텍스트 기록 | P1 |
| adSettings | 광고 실험 여부와 위치 관리 | P2 |
| tag | 향후 태그 정규화가 필요할 때 추가 | P2 |

## 4. 운영 흐름

1. 운영자는 Sanity Studio에 로그인한다.
2. project 또는 story 문서를 작성하고 공개 가능 여부를 확인한다.
3. 공개 발행 시 Webhook이 Astro 정적 빌드를 다시 실행한다.
4. 배포 후 운영자는 /admin 운영 포털에서 배포 체크리스트와 외부 통계 도구를 확인한다.
5. 접속 통계, 검색 성과, 광고 성과는 각 외부 서비스에서 확인한다.

## 5. /admin 운영 포털 정책

- /admin은 콘텐츠 CRUD 화면이 아니다.
- /admin에는 가짜 저장, 가짜 등록, 가짜 삭제 버튼을 두지 않는다.
- /admin은 Sanity Studio, Google Analytics, Google Search Console, 네이버 애널리틱스, 배포 체크리스트, 콘텐츠 운영 기준으로 가는 링크와 설명만 제공한다.
- /admin은 noindex와 robots disallow를 적용한다.
- 실제 배포에서는 Cloudflare Access, Vercel Protection, Netlify Basic Auth 같은 호스팅 레벨 접근 제어를 적용하거나 별도 내부 도메인으로 분리한다.
- 클라이언트 단의 단순 비밀번호 입력은 보안 대책으로 보지 않는다.

## 6. 단계별 도입

| 단계 | 작업 | 우선순위 |
| --- | --- | --- |
| 1 | 현재 Markdown 스키마를 기준으로 Sanity schema 초안 작성 | P0 |
| 2 | project, story 문서 타입 구현 | P0 |
| 3 | Pulda 공식 웹사이트 리뉴얼, 은조 아임웹 홈페이지, 첫 스토리 샘플 이전 | P0 |
| 4 | Astro 데이터 로더를 Sanity fetch 방식으로 전환할지, Markdown 병행으로 둘지 결정 | P0 |
| 5 | 발행 Webhook과 배포 훅 연결 | P0 |
| 6 | /admin 접근 제어와 운영 링크 확정 | P0 |
| 7 | siteSettings, mediaAsset 도입 | P1 |
| 8 | 태그/카테고리 탐색과 광고 설정 도입 여부 판단 | P2 |

## 7. 보류 기능

- 권한별 워크플로우
- 미리보기 전용 인증 페이지
- 사이트 내부 통계 대시보드
- 태그/카테고리 화면 필터
- 전문 검색 기능
- 폼/CRM 연동

## 8. 리스크

- 무료 플랜의 public dataset 특성상 내부 정보를 저장하면 안 된다.
- CMS 연결 후 빌드 Webhook이 실패하면 공개 사이트 갱신이 지연될 수 있다.
- 콘텐츠 필드가 과도하게 늘어나면 운영자가 작성하기 어려워질 수 있다.
- /admin을 공개 URL에 그대로 배포하면 noindex만으로는 접근을 막을 수 없다.
- 통계 도구와 광고 스크립트는 개인정보 고지, 성능, 브랜드 인상에 영향을 줄 수 있다.
