# 요구사항정의서

- 문서 상태: Draft / Living Document
- 기준일: 2026-07-04

## 1. 개요

Pulda 웹사이트는 브랜드 소개, 프로젝트 포트폴리오, 기업 블로그, 문의 유도를 수행하는 공식 웹사이트다. 사용자는 Pulda의 철학과 역량을 빠르게 이해하고, 실제 프로젝트 사례와 사고 과정을 확인한 뒤 문의할 수 있어야 한다.

현재 구현은 Astro 정적 사이트와 Markdown 콘텐츠를 기준으로 하며, 운영 단계에서는 Sanity Studio를 실제 콘텐츠 관리 도구로 도입한다. 사이트 내부의 /admin은 직접 편집하는 CMS가 아니라 운영자가 Sanity, 통계, 배포 체크리스트로 이동하는 운영 포털로 정의한다.

## 2. 사용자 유형

| 사용자 | 목적 | 주요 행동 |
| --- | --- | --- |
| 잠재 고객 | Pulda의 역량과 태도 확인 | 메인 탐색, 프로젝트 확인, 문의 |
| 파트너/협업자 | 작업 방식과 기준 파악 | 소개/스토리 확인, 연락 |
| 내부 운영자 | 콘텐츠 발행과 유지관리 | Sanity Studio 접속, 프로젝트/스토리 작성, 배포 확인 |
| 검색 유입 사용자 | 특정 글 또는 사례 확인 | 상세 페이지 진입, 관련 페이지 이동 |

## 5. 콘텐츠 요구사항

- 프로젝트는 기획 의도, 문제 정의, 진행 과정, 산출물, 결과, 리뷰를 담는다.
- 프로젝트 상세는 다음 수주를 위한 전시 창구이므로 텍스트 요약만이 아니라 시각 자료 중심의 설득력을 가져야 한다.
- 스토리는 개인적 이야기, 시장 동향, 공지사항, 작업 노트를 담는 기업 블로그로 운영한다.
- 소개 페이지는 메인과 중복을 줄이고 Pulda의 판단 방식과 협업 태도를 선명하게 한다.
- 태그/카테고리 화면 노출은 글이 충분히 쌓인 뒤 결정한다.
- 운영 중 망가진 외부 웹사이트 캡처는 그대로 보존하지 않고, 초기 시안 또는 관리된 포트폴리오 자산으로 대체할 수 있어야 한다.

## 6. 제약사항

- 현재 기준 프로젝트는 site/ Astro 사이트다.
- site/dist/는 빌드 결과물이므로 직접 수정하지 않는다.
- Sanity, 배포, 도메인, 메일 같은 외부 상태 변경은 별도 승인 후 진행한다.
- Sanity Free 플랜의 공개 데이터셋에는 공개 가능한 콘텐츠만 저장한다.
- 클라이언트 비밀번호만으로 /admin을 보호하는 방식은 보안 대책으로 보지 않는다.
- 접속 통계 원본 데이터와 광고 수익 데이터는 각 외부 서비스에서 관리하며, 사이트 내부에는 민감한 키나 통계 원본을 저장하지 않는다.
